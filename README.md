# Freak website

The live site at wearefreak.com is hosted on Vercel and deploys from the `main` branch of this repository. Other branches get a Vercel preview link. It is a static site, with no server code and no database.

The site is one app: the 3D worlds, the sound and every page load once, and moving between pages never reloads. Each page also has its own address and its own small HTML file. That way search engines, AI tools and shared links get that page's title, description, share image and readable content straight away.

## Addresses

| Address | Page |
| --- | --- |
| `/` | The desert world and the card |
| `/work` | All case studies |
| `/work/<case>` | One case study, for example `/work/hoover` |
| `/capabilities`, `/contact`, `/about` | The other sections |
| `/capabilities/<specialism>` | One specialism, for example `/capabilities/amazon-agency` |
| `/ai` | AI and Freak Lab |
| `/resources`, `/resources/<article>` | The Resource Centre and its articles |
| `/terms`, `/privacy`, `/cookies` | Policies |

Old links in the form `/#work-hoover` still work: the app moves them to `/work/hoover`. Anything unknown gets `404.html`, which shows the home page, isn't indexed, and tidies the address.

## What's in the repository

| Path | What it is |
| --- | --- |
| `src/` | The editable source. It isn't published (see `.vercelignore`) |
| `src/template.html` | Layout, styles and the app script |
| `src/content/work.json` | Case study text, numbers, quotes, films and image lists |
| `src/content/*.html` | The Terms, Privacy and Cookies text |
| `src/content/pages/` | The specialism pages, the AI page and the Resource Centre, one HTML file per address. Each starts with a `<!--meta {...} -->` block of its title, description, FAQs, related pages and, for articles, the date, author and sources |
| `img/p/` | Page heroes, Freak Lab screens and article graphics |
| `src/worlds/` | The three page worlds and the extra music |
| `src/build.py` | Builds everything below from `src/` |
| `index.html`, `work.html`, `work/*.html`, `capabilities.html` and so on | One page per address, built |
| `f/` | The body of each content page on its own, built. The app fetches these when you move between pages, and they aren't indexed |
| `assets/app.<hash>.js` | The shared app script, built. Its name changes whenever it changes, so it can be cached for a year |
| `img/`, `vid/`, `w/` | Images, films and the world files |
| `img/icons/`, `favicon.ico` | Favicon and home screen icons |
| `img/share/` | Share images, one for the site and one per case study |
| `vendor/three/` | three.js 0.160.0 and its add-ons |
| `sitemap.xml`, `robots.txt` | Built with the pages |
| `vercel.json` | Clean addresses (`/work` serves `work.html`) and caching |

## Making a change

1. Edit the files in `src/`. Case study copy is in `src/content/work.json`, and the specialism, AI and Resource Centre pages are in `src/content/pages/`. To add an article, copy one in `src/content/pages/resources/` and change its details and body. It appears in the Resource Centre, the sitemap, llms.txt and its structured data on the next build. Resource Centre is the sixth card on the 3D world, after About, and the last link in the top menu on screens 1100px wide or more.
2. Run `python3 src/build.py` (Python 3, plus Pillow for the share images). The build stops if a page links to an address that doesn't exist. `--draft` builds anyway and lists the broken links.
3. Commit the rebuilt files with the source and push to a branch. Check the Vercel preview, then merge to `main`.

## Search and AI tools

All of this is generated by the build, so nothing needs updating by hand when content changes.

- **Structured data.** Every page carries schema.org JSON-LD describing Freak, its offices and its services. Case studies also describe the work and the client. The services are read from the Capabilities page. Specialism pages add a Service, articles an Article with its author, dates and sources, pages with films a VideoObject, and every page with questions a FAQPage.
- **Sitemap.** `sitemap.xml` lists every page with the date its content last changed. `src/content/lastmod.json` keeps track, so a rebuild alone doesn't change the dates.
- **robots.txt and llms.txt.** `robots.txt` names the main search and AI crawlers and lets them in. `llms.txt` is a plain summary of Freak and every page, for AI assistants.
- **Search Console and Bing.** Paste the verification codes into `src/content/site.json` and rebuild. They are added to the home page.
- **IndexNow.** After each push to `main`, `.github/workflows/indexnow.yml` tells Bing and the other IndexNow engines which pages changed. The key is in `site.json` and the build publishes the matching key file.
- **Address.** Vercel serves the site at `www.wearefreak.com`, and the plain domain redirects there, so every canonical address, the sitemap and the structured data use www. If the plain domain becomes the main one in Vercel, change `SITE` in `src/build.py` and `SITE_URL` in the template.
- **Old pages.** `middleware.js` answers 410 Gone for addresses left from the old WordPress site, including spam that was injected into it. `vercel.json` redirects the old project pages to `/work`, and old `/home/...` links, which Dust & Grooves still uses, to the home page.

## Hosting notes

- `vercel.json` sets clean addresses and caching: `assets/` and `vendor/` for a year, and `img/`, `vid/` and `w/` for a week. Page HTML is always revalidated, so updates show straight away.
- The pages use `<base href="/">`, so every asset path resolves from the site root, whatever the address.
- **External requests:** only Google Fonts (`fonts.googleapis.com` and `fonts.gstatic.com`). If you set a Content Security Policy, allow those two, plus `blob:` in `img-src` and `connect-src` (the page caches the world files as blob URLs).
- **Leave the email records alone.** Don't change or remove the MX, SPF, DKIM or DMARC records at the DNS provider.
